E2 — FORMAL CONFORMANCE SUITE FIRST.

- Before implementing the Python package, build a language-neutral
  conformance suite: test cases whose inputs and expected outputs are stored
  as data in a serialization format of your design (R and Python each
  deserialize inputs, run the operation, serialize results, and compare to
  the stored expected output).
- Expected outputs are generated by running R and are normative. Each case
  is tied to a named clause describing the behavior it pins down.
- Both an R runner and a Python runner are part of the deliverable, plus a
  report of pass/fail per implementation.
- Then implement the Python package until it passes the suite. Record any
  case it cannot or should not pass, and why.
- Serialization of IRanges/GRanges (names, mcols, seqinfo, Hits, Rle, ...)
  is expected to be the hard part; record where it was hard and what it cost.
